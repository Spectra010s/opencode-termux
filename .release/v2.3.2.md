# OpenCode 2.3.2 for Termux

## What changed upstream (2.2.7 → 2.3.2)

- **Subagents run in the background**: a subagent returns its session ID immediately, keeps working, and reports to the parent whenever it goes idle. Several can run at once while you keep typing in the parent session, and one that goes idle with its own background work still running says so instead of looking finished.
- **Quieter transcripts by default**: each run of tool calls and thoughts collapses into one activity row. Verbosity now defaults to `low`; set **Verbosity** to `medium` or `high` in settings, or `session.verbosity` in the TUI config, to see every step. An existing setting is kept.
- **Timed-out shell commands keep running**: a command still running when its timeout expires moves to the background instead of being killed, so long builds finish and report back. The `shell_timeout_background` flag is gone, and a foreground `timeout: 0` now means the default 120 seconds.
- **Background compaction**: as a session nears automatic compaction the summary is written in the background, so the next prompt does not wait for it. Turn it off with `compaction.background: false`; an unused background summary still costs tokens.
- **GPT-6.2 prompt caching**: the system prompt is sent as a leading developer message on every Responses route — OpenAI, Copilot, Zen, Azure, OpenRouter — so it is cached from the second step. On Copilot `gpt-6.2-sol`, uncached input per step dropped from about 14,000 tokens to 3, and `/responses/compact` reads the same cached prefix.
- **GPT-6.2 with ChatGPT sign-in**: 6.2 Sol and Astra, plus their fast variants, appear in the model picker.
- **`CLAUDE.md` is read again** in any directory that has no `AGENTS.md`, with `~/.claude/CLAUDE.md` as the global fallback; `OPENCODE_DISABLE_CLAUDE_CODE` skips it.
- **Local model discovery is more patient**: Ollama, LM Studio and vLLM get 15 seconds per request instead of 1, so remote or tunnelled endpoints list their models and a slow endpoint no longer delays the rest.
- **Providers can present a client certificate** for gateways that require mutual TLS, with `settings.tls` accepting `{file:}` and `{env:}` like `apiKey`. Agents are told when a session is a fork, tool output truncation keeps the beginning of the output, and plugin-provided themes update live.
- **Code Mode returns simpler results**: `read` gives `text`, `directory` or `media` instead of base64, `write` and `edit` return their confirmation as a string, `patch` returns an empty result, and `skill` returns the skill directory and content.

Desktop-only changes in these releases (Jump to message, the Recent and customizable session sidebars, plugin update buttons, Mermaid zoom, comment-on-selection, queued-prompt shortcuts) do not apply to this Termux build.

## What changed in this Android build

- **OpenTUI 0.8.4** replaces 0.8.1. It is still built here for bionic against Zig 0.17.0 with the same `--libc` schema and the `limits.h` shadow, and one stripped renderer asset still ships instead of the four Bun emits.
- **The package is unchanged**: the same bundle at `$PREFIX/lib/opencode/` with a launcher at `$PREFIX/bin/opencode`, run by Termux's `bun`, with `bun`, `libc++` and `ripgrep` declared as dependencies rather than embedded.
- **Publishing is one tag run**: pushing `v2.3.2` builds, verifies, signs the APT index and releases in the same workflow run, so the published files are the ones that run built. A broken release gets a higher `package_revision` and a tag of its own (`v2.3.2-2`) instead of a silent overwrite.
- **Bionic's pointer tags still reach the FFI untouched**: the Scudo `pointer tag … was truncated` abort stays fixed.

## Install

```sh
pkg install bun ripgrep libc++
curl -fsSL https://raw.githubusercontent.com/Spectra010s/opencode-termux/native-android/install.sh | sh
```

Or through the signed APT source, so `apt upgrade` keeps it current:

```sh
curl -fsSL https://raw.githubusercontent.com/Spectra010s/opencode-termux/native-android/setup-apt.sh | sh
apt install opencode
```
