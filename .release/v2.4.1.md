# OpenCode 2.4.1 for Termux

## What changed upstream (2.3.2 → 2.4.1)

- **New TUI look**: the new designs ship on by default and the theme named `opencode` is the new one. The previous default is kept as `opencode-classic` (`opencode2` still aliases `opencode`), and **New designs** in the Experiments dialog turns the old layout back on.
- **Automations**: the agent can schedule a prompt, a Code Mode script or a fixed shell command to run once, on an interval, on a cron schedule or when a connected MCP server pushes an event. `/automation` manages them, a shell action asks for approval once when it is created, and `"automations": false` turns the feature off. MCP push delivery, heartbeats and reconnects ship with it.
- **Video generation**: with a provider that has a video model, `generate_video` renders in the background, survives a server restart and saves the finished file into the workspace. `experimental_image_generate` is now `generate_image`; permission rules are mapped automatically, but saved "always allow" approvals ask once more.
- **Plugins that follow a version update themselves**: `name@latest`, a version range, a Git branch or a Git `semver:` range is checked at startup and every 24 hours, and a newer match is installed and reloaded without a restart. A range stays inside its range, and a new version that fails to load leaves the previous one running.
- **`GITHUB_TOKEN` no longer signs in GitHub Copilot**, which fixes Copilot being picked up from environment variables that git tooling and Actions set. Use `COPILOT_GITHUB_TOKEN` or OAuth.
- **MCP servers negotiate the newest protocol first**, falling back to the legacy handshake; set `protocol: "legacy"` on a server that misbehaves.
- **The prompt cache survives a compaction**, long goal sessions stop paying for an extra cache write, and compaction no longer keeps more history than `keep.tokens` allows.
- **`/models` lists config-only providers** such as Ollama without a `/connect` login, and a slow project no longer leaves the model picker empty while it loads.
- **Shell commands the scanner cannot analyse ask for permission** instead of failing outright, and a matching `shell` deny rule still blocks them. A command that ends without an exit code now says why.
- **`edit` and `patch` refuse to rewrite a file that is not valid UTF-8** instead of replacing every Latin-1, cp1252 or GBK byte with `�`.
- **Code Mode** scripts can define getters and setters, errors carry a `stack`, built-ins match Bun (`toLocale*`, base64 options, `Buffer` slices), and `tools.opencode.session.rename` and `.move` replace the old dotted paths — direct tool names and permission actions are unchanged.
- **TUI plugins need OpenTUI 0.9.4**: `@opencode/plugin` requires `@opentui/core` and `@opentui/solid` 0.9.4 or later, and a renderer passed to `registerCodeBlockRenderer` now receives an OpenTUI block (`block.text`) instead of a Markdown token, so `codeBlockStyle` and `escaped` are gone.
- **Smaller fixes**: a revoked ChatGPT sign-in asks you to connect again instead of failing every prompt with a 400, stored blobs are deleted a week after they are written, config reloads only when a file that feeds it changes, `opencode <name>` prints help instead of a stack trace, a FIFO passed to `opencode run` is rejected immediately, and the background service starts on a slow disk with a large write-ahead log.

Desktop-only changes in these releases (the built-in browser pane and its extension profile, the Windows taskbar status, desktop keyboard shortcuts and the unread `/btw` dot in the side panel) do not apply to this Termux build.

## What changed in this Android build

- **OpenTUI 0.9.4** replaces 0.8.4, built here for bionic against **Zig 0.17.1** with the same `--libc` schema and the `limits.h` shadow, and one stripped renderer asset still ships instead of the four Bun emits.
- **Four guard patches are gone**: 0.9.4 clamps the buffer virtual-line, draw and renderer clip paths itself, so those patches are dropped instead of kept in place.

## Install

```sh
pkg install bun ripgrep libc++
curl -fsSL https://raw.githubusercontent.com/Spectra010s/opencode-termux/native-android/install.sh | sh
```

Or through the signed APT source, so `pkg install opencode` picks up new versions:

```sh
curl -fsSL https://raw.githubusercontent.com/Spectra010s/opencode-termux/native-android/setup-apt.sh | sh
pkg install opencode
```
